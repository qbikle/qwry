# Decisions (ADR-lite; one line each: what + why)

- 2026-06-12 · Tauri 2 over Electron/SwiftUI: small/fast/native feel; Rust core for streaming perf.
- 2026-06-12 · tokio-postgres over sqlx: need RowDescription `table_oid()`/`column_id()` for editable results, CancelToken, notices.
- 2026-06-12 · CodeMirror 6 over Monaco: ~1MB vs ~5MB, faster in WKWebView; intellisense quality comes from our completion engine either way.
- 2026-06-12 · Custom DOM grid (TanStack Virtual) over Glide Data Grid: full UX control; Glide is the fallback at P2 checkpoint.
- 2026-06-12 · SSH tunnels via system `ssh -L` subprocess: respects ~/.ssh/config; russh only if subprocess proves flaky.
- 2026-06-12 · Passwords in macOS Keychain (keyring crate); rusqlite app-db stores everything else.
- 2026-06-12 · JSON row values over Channel v1; binary/Arrow only if profiling demands.
- 2026-06-12 · zustand for state; `motion` for springs; lucide icons; cmdk palette.
- 2026-06-12 · `time` pinned to 0.3.47 in Cargo.lock: 0.3.48 breaks tauri-utils 2.9.2 with E0119 (conflicting From impls). Unpin when tauri-utils ships a fix; don't `cargo update` blindly.
- 2026-06-12 · keyring crate pinned to v3 (apple-native): v4 is a restructured meta-crate needing store init; v3 API is stable and sufficient.
- 2026-06-12 · Execution uses PG **simple protocol** (`simple_query`): every type arrives as wire text (psql-identical), multi-statement native. P5 editability metadata comes from a separate `prepare()` (RowDescription table_oid/attnum) without re-executing.
- 2026-06-12 · TLS = rustls with no-verify ServerCertVerifier ≈ psql `sslmode=require` semantics (RDS works out of the box); `prefer` tries TLS then falls back to plain.

### Mission upgrade (2026-07-02)
- 2026-07-02 · Goal changed from "releasable v0.5" (endpoint) to **surpass every mainstream Postgres client**: no finish line; v0.5 stays a waypoint/version cap for the current push. Two invariants outrank all feature work: (1) never feels slow at any data scale, (2) never lies about or corrupts data. Feature count only grows.
- 2026-07-02 · `docs/GAPS.md` is the ranked gap census (from a 13-workstream code+competitor audit; raw reports in `docs/audit-2026-07/`). Roadmap milestones draw from it: correctness ledger (GAPS §1) before features; the correctness keystone is **statement-at-a-time execution** in the driver (replaces whole-buffer `simple_query`); prerequisite for matched≠1 rollback, honest multi-statement results, tx-state tracking.
- 2026-07-02 · Promotions locked: run-statement-under-cursor and selection-stats-in-status-bar are P0 (v0.4); v0.35 = Correctness Milestone. Leapfrog features (GAPS §4: run-CTE-standalone, reverse-FK lookup, inverse-SQL undo, impact estimates…) are the beyond-v0.5 identity; build those before parity-polish.
- 2026-07-02 · **Multi-statement runs = psql autocommit semantics** (statement-at-a-time `simple_query`, stop on first error, earlier statements stay committed), NOT an atomic implicit transaction (Postico's model). Rationale: the whole-buffer form made the UI lie (reported-committed work silently rolled back by a later error) and broke VACUUM/CREATE INDEX CONCURRENTLY. Explicit BEGIN/COMMIT still span statements on the tab's session. A "run script atomically" toggle can layer on later. Error positions are rebased to whole-buffer CHAR offsets in the driver (`StmtSpan.char_offset`).
- 2026-07-02 · **Session timeouts: statement_timeout=5min + idle_in_transaction=10min at connect.** Deviates from locked decision #6 (30s): without a Settings escape hatch, 30s would kill legitimate analytics queries on big staging tables daily. 5min is the interim never-hangs-forever net (keepalives 30s/10s×3 handle the dead-tunnel case in ~1min); revisit the number when Settings (⌘,) lands.
- 2026-07-02 · **ROW_CAP auto-cancel is best-effort by design**: the driver cancels its own drain when the cap is crossed on the last statement, but a fast query legitimately wins the race and completes as a normal capped drain. Both paths return Ok + capped; a 57014 is only swallowed when WE fired the cancel (user ⌘. still errors through).
- **Prod safe-mode is server-side, per-session** (2026-07-03): `is_prod` → `default_transaction_read_only=on` in connect options (every session incl. spares), unlock = `SET … = off` on ONE tab's session behind a confirm. Chosen over client-side SQL sniffing: the server can't be fooled by CTEs/DO blocks/functions. Caveat: PG read-only still permits writes to existing TEMP tables; acceptable (no persistent data at risk).
- **Statement timeout is an app-level setting applied at connect** (2026-07-03): stored in useSettings (300s default, 0 = none), passed per `ipc.connect`; existing sessions keep their timeout until rebuilt. Per-profile override deferred until someone needs it.
- **⌘⇧F = format in the editor, filter-focus elsewhere** (2026-07-03): CodeMirror keymap preventDefaults first, window listener bails on defaultPrevented; one chord, two context-correct meanings.
- **Active tab restore via localStorage, not appdb** (2026-07-03): UI nicety, not data: losing it is harmless, so no migration/schema cost.
- **Per-connection workspaces** (2026-07-06): tabs carry `profile_id`; visibility = own ∪ pinned ∪ legacy-null. Pins are the cross-connection mechanism (origin-colored badge). Legacy tabs adopt-on-edit rather than bulk-migrate (no wrong guesses, no disappearing tabs). Unpin with a dead/foreign origin adopts the current connection. DB-switcher clones get fresh workspaces (different profile id); deliberate: different database, different tabs.
- **Commits are ONE batched simple-query message** (2026-07-06): `BEGIN;U₁;…;Uₙ` in one round trip, per-statement RETURNING counts verified from the single result stream, COMMIT/ROLLBACK as trip two; 2 RTTs for any N. Result-set accounting must be exact (n+1 sets) or the batch is refused+rolled back; any error mid-batch rolls back everything. Verify-then-commit semantics unchanged, only the transport shape.
- **Edit mappings are frontend-fed, trusted-but-verified** (2026-07-06): preview/apply/delete accept the EditabilityMap+snapshot-names the frontend already holds (zero catalog trips; preview = zero server contact), and `editability` accepts snapshot identity hints (1 RTT). Safety: incomplete hint → silent server derivation; snapshot table must match the map's server-derived dotted name (cross-DB oid collision guard); stale hints can only end in rollback (SQL error or matched≠1). SQLSTATE class-42 → refetch map; preview retries once silently, apply NEVER auto-retries; it regenerates the preview with a "schema changed" notice. Commit replays the exact stashed preview inputs (byte-for-byte guarantee).
- **Schema snapshots persist per profile (stale-while-revalidate)** (2026-07-06): appdb `schema_cache` keyed profile_id + `connSig`; hydrate at connect START for t=0 sidebar/completion, real introspect refreshes behind it. Ordering rule: hydrate never overwrites anything, server fetch always wins; no timestamps needed. Raw-JSON introspect passthrough rejected (escaping bloat + loses Rust-side validation).
- **SSH tunnels keyed and shared by SPEC, not profile** (2026-07-06): DB-switcher clones ride one ssh process. `profile_specs` tracks bindings; invalidate/delete unbinds the profile and drops the tunnel only when no other profile shares the spec (a shared tunnel drop would kill sibling sessions). A repointed profile computes a new spec and naturally gets a fresh tunnel.

### v0.7.0-bedrock
- 2026-07-18 · appdb schema versioned via `PRAGMA user_version` + numbered migrations, one transaction each, stamped on commit (replaces the `let _ = ALTER` swallow-all). v1 = pre-versioning baseline: CREATE IF NOT EXISTS + column-checked ALTERs, so a legacy unversioned DB is stamped in place with data intact and real errors propagate. List reads (profiles/tabs/saved/history) skip-and-log corrupt rows: one bad row costs one row, never the whole list. History rows carry status ok/error/cancelled (failed + ⌘.-cancelled runs are recorded from the frontend catch path, 57014 = cancelled), per-row SQL capped at 20k chars with a marker, table pruned to newest 20k rows on insert. `tauri-plugin-single-instance` registered before every other plugin; a second launch focuses the existing window instead of racing the first for the shared appdb.
- 2026-07-18 · **Tx state is driver-lexed** (tokio-postgres discards ReadyForQuery's status byte at every site; checked 0.7.17 source): splitter statement-heads (BEGIN/START, COMMIT/END, ROLLBACK/ABORT, ROLLBACK TO un-fails, AND CHAIN stays in-tx, PREPARE TRANSACTION → idle) + error outcomes fold into idle/in-tx/failed-tx per session, surfaced as a dedicated `tx-state` event (not a QueryEvent). Known limit: `CALL proc()` with internal COMMIT drifts the tracker, but only in the fail-safe direction (worst case a SAVEPOINT errors; nothing can be silently committed). Ride-along: ROW_CAP auto-cancel is disabled inside an open tx (our own 57014 would abort the user's transaction).
- 2026-07-18 · **Edits inside a user transaction = SAVEPOINT/RELEASE** (`ROLLBACK TO`+`RELEASE` on verify failure); the outer tx is NEVER committed or rolled back by an edit. `committed:true` there means "applied into the open tx"; durability is the user's COMMIT (tx chip stays lit). Batch wrapper contributes exactly one result set in both modes, keeping n+1 stream accounting.
- 2026-07-18 · **ctid guards use `= 'v'::cast` / `IS NULL`, not IS NOT DISTINCT FROM**: semantically identical for known old values, and stays indexable; json/xml/geometric types (no `=` operator) compare via `::text`. Guard columns: every untruncated same-table result column, deduped by attnum. Same guard grammar on edit and delete paths.
- 2026-07-18 · **Table identity is `{schema, name}` end-to-end** (`table_refs` in EditabilityMap/EditMapHint, schema+name on TableIdentityHint); the dotted `tables` string survives as display-only. Casts are captured pre-qualified at editability time (`pg_catalog` bare, else quoted+qualified; `"char"` force-quoted: bare `::char` silently means bpchar(1)).
- 2026-07-18 · **Cancel escalates out-of-band**: CancelToken (1.5s deadline) → busy-poll ≤1.2s → `pg_cancel_backend` over a fresh connection built from the stored Config (5s deadline); `pg_terminate_backend` is a separate user-confirmed command on the force-disconnect hatch, never automatic. Internal ROW_CAP cancel uses the raw token (escalation would self-deadlock on the busy poll).
- 2026-07-18 · **Overlay z-index derives from escStack position** (BASE 50 + depth via `pushOverlay`); stacking order can't lie about key routing. escStack ignores Esc while `e.isComposing`.
- 2026-07-18 · **Draft-row grammar**: untouched = DEFAULT, touched-empty = `''`, ∅ = NULL; touched-state per cell. Revised same day after audit: an EMPTY field in a multi-cell TSV spread-paste stays untouched (DEFAULT, the spreadsheet convention; `''` into numeric/date columns was hostile); a deliberate `''` remains reachable per cell (type + clear, or single-cell paste).
- 2026-07-18 · **Hint-fed plans carry attname identity guards** (audit fix): every hint-named column used in a hinted statement (SET + locator + guard) gets `(SELECT attname FROM pg_attribute WHERE attrelid=… AND attnum=…) = 'name'` ANDed into the WHERE; an external RENAME+ADD between snapshot and ⌘S now rolls back honestly (matched 0) instead of writing the wrong column. Derived (non-hint) plans carry none; still 2 RTTs.
- 2026-07-18 · **Savepoint hygiene** (audit fix): per-batch unique savepoint names (`qwry_edit_sp_{n}`) so our cleanup can never roll back a user's identically-named savepoint; batches REFUSE to start in a failed tx ("current transaction is aborted; ROLLBACK first"). Failed COMMIT/END (deferred constraints) folds Idle, matching the server.
- 2026-07-19 · **Sort is a chain** (spelunk): `setSortChain(SortKey[])` ({column, dir, nulls?}) is the browse sort API; per-key NULLS FIRST/LAST are keyset ladder VARIANTS (default placements emit byte-identical SQL to before, proven); tiebreaker inherits the FIRST key's direction, PK-in-chain absorbed. Supersedes "no NULLS clauses" phrasing in the 07-18 keyset entry. Editor results: stable client-side multi-sort in the existing view-map slot.
- 2026-07-19 · **Raw-WHERE mode owns the WHERE entirely** (spelunk): builder rows can never filter behind the user's back while raw mode is on; one `compiledWhere` feeds pages, count, and histograms. Jump-to-row = honest OFFSET page-1, then scrolling re-anchors keyset from the landed page (proven gapless).
- 2026-07-19 · Sidebar pins persist in localStorage per profile as {schema,name} pairs (UI nicety, active-tab-restore precedent). Introspect v2 requires PG 10+ (pg_sequence join); pre-10 errors the whole batch; ledgered, PG 9.6 is EOL.
- 2026-07-19 · **ctid keyset is triple-gated** (tempo audit): ordinary relkind only, `relhassubclass=false` (inheritance children have colliding ctids: TimescaleDB hypertables), AND reltuples estimate ≤1M (TID scans have no pathkeys; ORDER BY ctid is a seq scan + top-N sort PER PAGE); missing metadata fails safe to offset fallback. Page-1 keys are PINNED on the tab: key drift (snapshot refresh) or a committed edit to a key column forces a full re-run, never a spliced append. Inherent residual (ledgered): concurrent writers move ctids between pages.
- 2026-07-18 · **Browse pagination is true keyset** (tempo): PK/ctid tiebreaker inherits the sort direction (uniform ORDER BY, page 1 included; total order requires it); row-value `(a,b)>(v…)` fast path only when uniform-dir AND catalog NOT NULL; otherwise OR-ladder with explicit NULL partitions; sort keys always treated nullable (stale snapshots); seek values are wire text + `::format_type` casts. Offset fallback ONLY for non-keysettable relations (views, partitioned-no-PK, ctid on PG<14, truncated seek cells), never wrong-rows keyset. loadMore appends one page on the tab session and skips history.
- 2026-07-18 · **pg_catalog functions cached in appdb keyed by server_version** (tempo): introspect stays one round trip: a count(*) probe rides the batch; count drift (extension into pg_catalog) or corrupt JSON = miss → refetch+re-persist. User-schema functions always live.
- 2026-07-18 · **Editor statement spans are incremental** (tempo): prefix reuse + 64KB growing re-lex window + suffix re-adopt on exact shifted restart; the FINAL span is always re-lexed (a trailing `;` can sit inside an unterminated comment; differential testing caught this). Completion context is capped at a 200KB window around the cursor with byte-identical output under the cap; sql-sync deliberately keeps one synchronous toString() per keystroke (0.016ms JSC rope) because ⌘S/close/quit read the store synchronously.
- 2026-07-18 · `history_search` LIKE-scans only the newest 5k rows (constant cost; FTS is the lift if older-match search is ever wanted).
- 2026-07-18 · `ConnState` gains `"error"` (failed connect ≠ never-tried gray); every existing consumer compares `=== "connected"` so it behaves as not-connected everywhere else.

### v0.8.1-timeline
- 2026-07-19 · **Undo OLD-capture is in-statement, zero extra RTTs**: `UPDATE t AS __t SET … FROM (SELECT <changed> FROM t WHERE <full-where> FOR UPDATE) __old WHERE <full-where on __t> RETURNING __old.*, __t.*, __t.<locator>`; the outer WHERE repeats the predicates (indexable, matched-count byte-equivalent; FOR UPDATE locks before capture so __old is the exact pre-image). PG 14–17 grammar; PG 18 OLD/NEW RETURNING unused. DELETE captures via RETURNING * + one catalog probe riding the batch (DDL blocked by the DELETEs' own lock).
- 2026-07-19 · **The undo artifact is a structured revert PLAN, not SQL text**: SQL regenerated by the same generator at undo time (nothing parsed); an applied undo mints its own inverse, so redo emerges with zero special-case code. Reverts: PK locators (post-commit values), NEW ctid + server-normalized value guards on ctid tables, attname identity guards always; GENERATED/identity-ALWAYS excluded from re-INSERTs (no OVERRIDING SYSTEM VALUE: honesty over magic; an undone delete of an identity-ALWAYS row gets a fresh id, ledgered).
- 2026-07-19 · **Undo re-enters run_verified_batch**: stale undo = matched≠1 = full rollback + "undo no longer matches". Offer is session-stamped (server re-checked), single-shot (consumed whether it commits or not, NEVER auto-retried), TTL 15min, invalidated on DDL/newer-commit/session-death; prod read-only refuses at the server (tested).
- 2026-07-19 · **Buffer time-machine views are read-only throwaway EditorStates**: the live draft is parked and every store-sync path is hard-gated while viewing, so a snapshot can never leak into tab.sql; restore = one undoable transaction. Snapshots ride appdb (v5) keyed per tab, deduped, capped 50.
- 2026-07-19 · .sql file links are session-only Tab fields (path + saved-text); persisting them needs a tabs schema column; deferred. Drag-drop uses Tauri window events (WKWebView never delivers HTML5 file drops with dragDropEnabled).
- 2026-07-19 · **CSV import: validate = a full rehearsal that ALWAYS rolls back; commit = ONE all-or-nothing tx** (timeline): both run identical batched 500-row multi-row INSERTs with `'v'::type` casts (cast names from live pg_attribute/pg_type, edit.rs cast discipline). Validate re-runs a failed batch row-by-row under savepoints to name exact bad rows (cap 50 + honest "more"); commit failure attributes the row via PG's char-position→tuple-span map, else names the batch range. `flexible(false)`: short/long rows are per-row errors, never padded. Header sniff rule: row 1 is a header ONLY on a type mismatch vs the data rows (all-match ⇒ headerless; never eat a data row); UTF-8 only, per-row errors otherwise. Fatal codes (25006 read-only prod, 25P02, 57014, 08*) abort instead of repeating.
- 2026-07-19 · import.rs carries byte-identical private copies of edit.rs `ql`/`qi`/cast rules with parity unit tests; edit.rs was concurrently owned in this wave so the helpers couldn't be made pub(crate); fold them into one shared module next quiet pass.
- 2026-07-19 · History panel: grouping is CLIENT-side over the unchanged history_search API: consecutive same-normalized-SQL+same-profile runs collapse to ×N (expand →/←, badge tints when a collapsed group hides non-ok runs); day dividers Today/Yesterday/date; per-connection chip pushes profile_id into the query, status chips filter client-side; absolute timestamp on hover, relative stays primary.

### v0.9.1-firstlight
- 2026-07-20 · **Hidden-until-painted launch**: the window is created `visible: false` and revealed by the frontend after startup data (profiles+tabs) settles + double-rAF post-paint; never an empty glass pane. window-state plugin runs with `StateFlags::all() - VISIBLE` (restoring visibility would defeat the hidden start); a Rust 5s fallback thread shows the window if the webview never boots. Corollary: any future "show earlier" change must keep all three pieces in sync.
- 2026-07-20 · **Store wiring pins the entry chunk**: stores with module-level cross-store `subscribe()` (edits, browser) are side-effect-imported in main.tsx. Lazy-chunking them starts their wiring late and desyncs active-tab state; same failure class as the HMR stale-store gotcha. Shell reads editor registries via `editor/editorBus.ts`, never from SqlEditor (which would drag CodeMirror into the entry chunk).
- 2026-07-20 · **One-line inputs never hold newlines**: draft cells with multiline text render a read-only ⏎ preview and edit through ValuePop (WebKit silently strips \n from input.value → state desync).
